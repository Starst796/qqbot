总开关与模型

触发

semantic 模式下，没被点名的群消息要过两道闸： 先按「主动接话抽签概率」抽签，抽中了才去走判定；两道都过才开口。
别用「允许接群友的闲聊」来降频率 —— 它管的是「判得准不准」， 关掉会把判定退化成「只在被点名时说话」（就是之前“大群不插话”的老问题）。 想少说几句就调抽签概率，或「限流与话痨度」里的每群每分钟上限。
「判定每分钟上限」是大群不插话的头号原因（大群几十条/分钟，额度几秒就打满）， 建议按群活跃度量级给（如 30~60）。抽签排在它之前，所以调低抽签概率也顺带省下判定调用。
「群内需 @ 机器人」仅在 at 模式下生效。

读图

图片会下载后内联给模型，模型必须支持图片输入（deepseek-flash 支持， deepseek-v4-pro 不支持）。

限流与话痨度

「每群每分钟最多说几句」才是话痨度的直接旋钮 （按群滑动 60 秒窗口计数）。建议 2~5；0 = 不限制。
「同群最小间隔」只管防连发：设成 1 秒约等于没有限制，别用它控制话痨度。 建议 5~10 秒。
复读侧另有自己的 60 秒冷却（跟读 / 学舌 / 接话对三条共享），所以实际总量 ≈ 本值 + 1。

工具调用（被 @ 时）

被 @ 时模型可按需调用工具（查时间、联网搜索、翻本群历史语料）， 群内自动接话永远不带工具，免得一次闲聊就多烧几轮调用。 「最多工具轮数」与「单次工具超时」是硬闸。
联网搜索需要 .env 里的 TAVILY_API_KEY（密钥不进配置文件， 因为面板接口会把它原样吐出来）；没配时模型会如实说没配好，不会编造搜索结果。
「按意图筛工具」开启后只在话题沾边时带上对应工具； 「允许模型发现低频工具」会给模型一个 tools_find 去现场找低频工具。

风格注入（RAG / 接话对）

接话对由真实相邻对话抽取（越像接话分越高），重建是离线动作——点下面的按钮触发。

学习型复读

复读只说群里已经出现过的话，不调用模型。屏蔽词命中即不学也不复读； 在下面的消息列表里点「拉黑此句」可自动写入「拉黑句」。 「机器人发言后静默」用于避让 AI 回复，防止两套回复同时出声。
「命中接话对就直发」补的是一块结构缺口：接话对原先只喂给 AI 调语气， 从不参与「要不要说话」的决策，所以“命中接话对也不插话”是必然的。 开启后用当前消息去接话对里做向量召回，命中就把当年那句接话发出去 —— 发不发仍受下面的冷却、去重、屏蔽词约束。相似度下限调低会更话多。

表情包设置

存储与检索

内存紧张可将 BAAI/bge-m3 换成 BAAI/bge-small-zh-v1.5（重启生效）。

拟人化

「短回复不拆」是最重要的一个旋钮：整段短于这个字数就绝不拆条， 并把换行压平后一条发出。真人不会把一句短话分两条发， 更不会在一个气泡里凭空空一行（模型很爱在两句话之间留空行，代码会压掉它）。 默认 30，建议 20~40；设 0 = 关掉这个兜底。
「注入输出格式约束」会在 system prompt 末尾追加一段“默认一条说完、最多两条”， 并明确覆盖人设里相反的格式要求 —— 如果你的人设提示词里还写着“一行一句”， 这个开关就是让它不再生效的（默认开）。
拆条规则：按行拆 → 片段短于「碎渣并回」就并到相邻片段 → 最多「一次最多几条」条， 超出并入最后一条；单条超过「长度上限」时按句末标点再切。
两种延迟别混淆：「最短/最长打字延迟」是首条之前等的（只等一次）； 「分条间隔」是每条之间等的。想更连珠炮设 100/300，想更慢条斯理设 800/1500， 设 0/0 就是连发。

服务控制

「重载配置」立即丢弃配置/检索缓存，不中断服务（限流、提示词、开关改完即生效）； 「重启服务」重启进程（约 3 秒，systemd 自动拉起），用于切换 embedding 模型等需要重新加载的场景。

NapCat 接入

native 模式下面板不再调 Docker：二维码与 WebUI token 从上面的目录读 （NapCat 自身也用 config/ cache/ logs/ 三个子目录），日志改读该目录下的 logs/； 「重启 NapCat」按钮会置灰，需手动重启进程。机器人本体（OneBot 连接）两种模式都一样。
